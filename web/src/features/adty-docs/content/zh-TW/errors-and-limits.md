# 錯誤碼和限制

錯誤使用 OpenAI 的格式：HTTP 狀態碼，加上帶 `error.message` 和 `error.code` 的 JSON。message 說明出了什麼問題，狀態碼告訴你該怎麼處理。

## 狀態碼

| 狀態碼 | 意思 | 怎麼處理 |
|---|---|---|
| 400 | 請求有誤，例如請求內容格式不對，或者模型不接受某個參數 | 修改請求；原樣重試還會失敗 |
| 401 | 沒帶 API 金鑰，或者金鑰錯誤、已停用、已過期、金鑰自己的額度用完了 | 檢查 `Authorization: Bearer sk-...` 請求標頭，以及[令牌](/keys)頁裡金鑰的狀態 |
| 402 | 需要付款。ADTY AI 餘額不足時回的是 403（見下一列），出現 402 一般是上游服務商回的 | 稍後重試；一直出現請聯絡客服 |
| 403 | 帳戶餘額不足（`insufficient_user_quota`），或者這把金鑰不能用該模型或分組 | [儲值](/wallet)，或者檢查金鑰的模型和分組設定 |
| 404 | 路徑錯了，或者模型不存在 | 檢查位址（要不要帶 `/v1` 見各用戶端的說明），以及[模型價格](/pricing)頁裡的模型名稱 |
| 429 | 你的帳號請求太多（`rate_limit_exceeded`），或者上游忙碌 | 等一下再試，見下面的限制說明 |
| 500、502、503 | 上游服務商出錯，或者這個模型暫時沒有可用通道 | 間隔逐漸拉長地重試；一直出現請聯絡客服 |
| 524 | 請求太久，連線被中斷（見下文） | 改用串流 |

被拒絕、回傳錯誤的請求不扣費。

## 按帳號的限制

帳號可能有三項限制，所有金鑰合起來計算：

- **RPM**：每分鐘請求數。
- **TPM**：每分鐘 tokens 數。
- **並行**：同時進行的請求數。

超過任何一項都回 429，並帶 `Retry-After` 回應標頭，告訴你要等幾秒。請等到這個時間再重試，不要馬上重試。如果你的業務需要更高的限制，請聯絡客服。

## 長請求請用串流

請求會經過 Cloudflare。連線上約 **125 秒**沒有任何資料，Cloudflare 就會把它中斷。非串流請求如果超過這個時間（輸出很長、推理模型、大段程式碼修改），就會被中斷，用戶端收到錯誤（通常是 524），即使模型其實還在生成。

設定 `"stream": true`。串流回應會馬上開始傳回資料，並一直保持連線，直到模型生成完畢。Claude Code、Codex CLI 和大部分聊天用戶端預設就是串流。
