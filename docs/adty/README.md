# adtyai-api 工程文档

adtyai-api 是 [QuantumNous/new-api](https://github.com/QuantumNous/new-api) 的二开，起点是上游 v1.0.0-rc.47，以后持续合并上游的新版本。为了合并顺利，改动尽量放在新文件里，上游文件只加挂载点或做删除（[conventions.md](conventions.md) 的约定 B）。实施方案（代号 WhiteRelay）和设计稿不在仓库里，下文的任务号都指实施方案里的任务。

## 这个 fork 改了什么

最初实施方案 P0–P12 已于 2026-11-01 完成阶段交付，后续全平台规格仍有未闭环项，真实 Cloudflare、Resend 账号联调仍留到上线前。下列说明已同步到 2026-11-14 的实现；每个功能的规则、后台入口、算例和当前限制见 [features.md](features.md)。

- **删掉的功能**：上游的订阅、兑换码（连同它的「购买链接」设置 TopUpLink）、上游邀请奖励，以及 Playground、模型部署管理和独立营销中心，前后端整条删掉，删除单独提交。删了什么记在 deleted-features.md；整个删掉的文件和目录另记在 deleted-paths.txt，合并上游的脚本（任务 1.7）和守卫测试（任务 1.6）读它，防止合并上游时把删掉的东西带回来。
- **上游的发布工作流**：docker-build、docker-image-branch、electron-build、release、sync-release-to-gitcode 五个 workflow 删掉（也在 deleted-paths.txt 里），镜像只由 `.github/workflows/adty-ghcr.yml` 构建，`ci.yml` 保留。本地的 712 个上游标签已经删掉（清单备份在仓库外的 `adtyai-api-upstream-tags-backup.txt`），`upstream` 远程设了 `tagopt --no-tags`，合并脚本把上游标签取到 `refs/upstream-tags/`，见 [upstream-merge.md](upstream-merge.md)。
- **充值**：统一接入易支付、BEpusdt、Stripe、Creem、Waffo 和 Waffo Pancake；BEpusdt 支持 TRC20、BEP20、Polygon、X Layer。Root 配置版本化支付场景，按服务、方式、通道、金额、币种、站点及用户身份限制实际下单，钱包只显示当前可用选项。订单记在 `adty_topup_orders`，冻结场景及网关事实，面额、加赠和优惠码加赠按现有规则入账、算佣金、写流水；已冻结订单的可信晚到回调不受后续停用影响。BEpusdt 还支持可信查询和回调丢失恢复。新订单赠金按支付方式比例快照计算，金额档位赠金不再写入。最低充值额等和钱有关的参数都在后台设置，没有内置值。
- **充值退款**：后台「充值对账」里的一个操作。只退没花掉的本金，赠金收回不退：按用户当前余额扣回这笔订单还剩的额度，余额最多扣到 0；按退掉的本金占本金的比例处理佣金。主站推广佣金按该比例扣回。分站邀请佣金按同一比例：还冻着的释放回原来源，已转余额的冲回用户余额，已外部打款的只记追偿。分站订单里站长出的加赠只按收回的部分还给站长。真正把钱退给用户在线下做，后台显示应退多少。
- **余额下限**：不允许透支。每个钱包请求都先预扣，余额不够直接拒绝（403），上游收不到请求；结算时实际费用比预扣多，最多扣到 0。没扣到的差额记入同一账户的短差额挂账，并暂停该账户新的付费请求；日志仍写 `admin_info.shortfall_quota`（只有管理员看得到）。上游原来余额够多时跳过预扣的「信任额度」对钱包不再生效。
- **推广返佣**：从旧项目移植（表 `referral_*`，接口 `/api/user/referral/*` 等），返佣比例沿用百分数，注册即有推广链接，只按充值面额计佣；订单里存返佣快照；退款时按退掉的本金比例扣回佣金。站长和分站客户不计邀请返佣。
- **后台分权**：普通管理员默认没有任何后台权限，由超级管理员逐项开启、随时可以关；系统设置、易支付通道的新增和密钥、管理员任免只有超级管理员能做。
- **站长分站（P11）**：正式分站由 Root 从主站已有用户创建，站长不可更换，转让入口必须拒绝。关站由 Root 发起，客户和存续团队迁入主站。站长界面只显示收益和保证金；经营钱包继续记账，但不展示，站长充值汇总返回 403。历史订单、异步任务、退款、结算和追回按原操作冻结的财务归属处理，不能按当前站长重算。分站客户的一级邀请佣金单独冻结，现金提现由该站站长审核；验收门仍未关闭。
- **营销与兑换码**：独立营销中心、群发及营销自动邮件、营销同意和偏好、注册来源采集及统计已删除。优惠码报价和写入已退役，历史行保留且不重算。充值额度只使用一种兑换码。关站、涨价等业务系统邮件保留。
- **员工、通知和财务**：分站员工有独立工作区和明确的只读或客户安全操作授权，权限由服务端逐次核对，撤权立即使旧会话失效；客户调额资金规则仍待补齐。通知支持发布、版本化已读回执，指定业务范围及部分角色角标仍未完成。用户可按站点筛选，财务可查看统一订单和冻结详情、追溯关联资金链，并按授权补查或处理退款。
- **数据库**：正式运行、部署、资金测试和验收只使用 PostgreSQL，不使用 SQLite 或 MySQL。不设最低版本或最高版本；测试时记录实际 `server_version_num`，版本不同不算失败。建议版本为 PostgreSQL 17，新部署优先使用 17，但不把 16、18 或其他版本排除在验收之外。缓存用 Redis。ADTY 启动时主库或日志库不是 PostgreSQL 就直接退出。仓库保留上游 SQLite、MySQL 兼容代码和已有单测，只用于避免破坏上游资产，不作为验收证据；这些测试缺失、未执行或失败，不阻塞验收。已有数据目录升级主要版本时，必须另建目录迁移并核对账目，不能直接换镜像启动，见 [deploy.md](deploy.md)。
- **版本号**：`.github/workflows/adty-ghcr.yml` 在镜像构建时生成 `VERSION`，前后端共用；`main` 为 `main-<短 SHA>`，标签构建为标签名，其他分支为 `<分支名>-<短 SHA>`，拉取请求为 `pr-<编号>-<短 SHA>`。仓库内空的 `VERSION` 是构建占位，web 的 `package.json` 版本独立维护；上游 v1.0.0-rc.47 只表示二开起点。
- **名字、Logo 和语言**：访客、调用 API 的人、上游服务商和浏览器开发者工具能看到的 New API，都换成 ADTY AI 或 adtyai。正式语言只有简体中文和英文；站名 ADTY AI 不翻译。已有的另外六种语言包可以留在仓库里，但不在选择器、首页或文档中承诺。Logo 换成「层叠网关」一套（`web/public` 下的图标、manifest、分享图），原稿和生成脚本在仓库外的 `adtyai-logo` 目录（`source/build.py`）。Go 模块路径不改；LICENSE、NOTICE、THIRD-PARTY-LICENSES.md、上游源文件头和页脚的上游署名都保留（AGPL）。
- **首页**：`/` 固定是英文，另外 7 种语言用 `/zh-cn`、`/ko` 这类网址；首页的标题、描述和正文写进网页源码，其余页面一律 noindex。
- **其他**：白色主题；按用户限 RPM、TPM、并发，开了 Redis 但计数不可用时拒绝而不放行；客户能看到的日志和任务不露渠道和倍率；人工调额留痕，且不能把余额调成负数；防邮箱枚举，验证码写不进共享存储时不发信；密码连续错误 8 次后锁定 15 分钟；主站发布了协议或隐私政策后，注册必须接受并留下系统日志；所有流式格式在等首字时都能发保活；分组有固定 ID，正式显示名只有简体中文和英文；官方价每天从 models.dev 同步，价格页显示节省比例；接入文档、推广计划、中英文条款和退款政策。统一工单和两个 Telegram 通知机器人是客服与提醒入口。不建设公开平台服务状态页，也不把外部客服挂件或 Telegram OAuth 当成通知绑定或工单系统。

## 和 AGENTS.md 不一致的地方

仓库根目录的 AGENTS.md 保留上游写给 AI 代理的通用规范，并补充本 fork 的站长不可更换、固定额度、支付场景和版本约定。下面四点说明本 fork 的具体约定，合并上游时一起核对：

1. **数据库**：ADTY 的正式运行、部署、资金测试和验收只使用 PostgreSQL。不设最低版本或最高版本；记录实际 `server_version_num`，版本不同不算失败。建议版本为 17，新部署优先使用 17，16、18 或其他版本不排除在验收之外。上游 SQLite、MySQL 兼容代码和已有单测照旧保留，只避免破坏上游资产，不作为验收证据；缺失、未执行或失败不阻塞验收。资金测试使用隔离的 PostgreSQL 和真实 Redis。已有数据目录升级主要版本时，必须另建目录迁移并核对账目，不能直接换镜像启动。
2. **对外的名字**：AGENTS.md 规定 New API 和 QuantumNous 的名称、标识「任何情况下不得修改」。本 fork 按执行层决定 21 和任务 8.9，把访客、调用方、上游服务商和浏览器能看到的名字换成了 ADTY AI 或 adtyai（cookie 名、错误类型、本地存储键、网页标题、Logo 等，改了哪些、哪些不改见 conventions.md 和任务 8.9）。LICENSE、NOTICE、THIRD-PARTY-LICENSES.md、源码版权头、页脚的上游署名、Go 模块路径 `github.com/QuantumNous/new-api` 都照旧保留。
3. **docs/adty/ 下的文档**：AGENTS.md 说没有用户明确要求时不要在 `docs/` 下新建文件。`docs/adty/` 下的文档都是按实施方案（约定 A：工程文档放 `docs/adty/`）或用户的要求建的，以后改功能时要同步更新这里的文档。
4. **语言**：正式语言只有简体中文和英文。已有八种语言包仍可留在仓库里，避免重写框架，但不是正式承诺。新的正式文案必须有中文和英文。根目录 AGENTS.md 已按这条同步。

## 各个文档的用途

- `README.md`：本文件，说明这个 fork 改了什么、各个文档的用途、和 AGENTS.md 不一致的地方。
- [features.md](features.md)：功能说明，给运营人员和接手的开发看。每个功能写做什么、规则、后台在哪里设置或操作、默认开还是关、相关的表和接口、已知的限制；涉及钱的都有算例。
- [conventions.md](conventions.md)：全局约定 A–I（代码放哪、怎么改上游文件、钱、权限和密钥、文案和语言、测试、提交、开发环境、已确认产品边界），每个任务都遵守。约定 I 与旧句子冲突时以约定 I 为准。
- [upstream-touchpoints.md](upstream-touchpoints.md)：改过的上游文件。每改一个上游文件记一行：文件、改了什么、为什么（约定 B）；合并上游时对照它解决冲突。
- [deleted-features.md](deleted-features.md)：删掉的功能，按功能列出删掉的文件、路由、表和列、配置项、前端目录和提交，以及有意保留的东西和理由。
- [deleted-paths.txt](deleted-paths.txt)：整个删掉的文件和目录，一行一个。合并上游的脚本（任务 1.7）和守卫测试（任务 1.6）读它。
- [upstream-merge.md](upstream-merge.md)：合并上游新版本的流程（实施方案第七节），以及合并脚本 `scripts/adty/merge-upstream.sh` 怎么处理冲突、什么情况下不跑。
- [deploy.md](deploy.md)：生产部署（任务 10.1、11.11）：`deploy/adty/` 下的 compose、Nginx、Cloudflare 网段和防火墙脚本、备份脚本怎么用，Cloudflare 面板怎么设，分站的泛解析和 Cloudflare for SaaS，真实 IP 验证，升级和回滚。
- [launch-checklist.md](launch-checklist.md)：上线检查清单（任务 10.2、11.11）。上线前逐条打勾：环境变量、后台设置、支付和推广实测、分站和营销、浏览器和客户端回归、备份演练、SEO。
- [baseline.md](baseline.md)：上游基线（任务 0.3）。记录上游 v1.0.0-rc.47 原样不改时 `scripts/adty/check.sh` 每一步的结果；这里记下的上游失败不算新失败（约定 F）。

`docs/` 整个目录不进 Docker 镜像（`.dockerignore` 里的 `docs` 一行）。
